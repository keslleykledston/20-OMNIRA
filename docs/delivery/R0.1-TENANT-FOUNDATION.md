# R0.1 — Tenant Foundation

**Status:** Ready for implementation  
**Backend:** Go  
**Objetivo:** entregar a primeira base funcional, segura e observável do OMNIRA.

## Resultado demonstrável

Ao fim do R0.1 deve ser possível:

1. autenticar um usuário;
2. criar/seedar Tenant A e Tenant B;
3. associar usuários via Membership;
4. acessar recursos do Tenant autorizado;
5. bloquear acesso ao Tenant não autorizado;
6. registrar auditoria;
7. observar request/trace/correlation;
8. publicar um evento via outbox;
9. verificar health/readiness;
10. executar tudo em ambiente local reproduzível.

## TenantContext

Estrutura conceitual:

```go
type TenantContext struct {
    TenantID uuid.UUID
    ActorID  uuid.UUID
    Source   AccessSource
}
```

`TenantContext` só pode ser construído após autorização.

Nunca:

```go
tenantID := request.Body.TenantID
ctx := NewTenantContext(tenantID)
```

Esperado:

```text
authenticated actor
  -> target tenant/resource
  -> authorize membership/grant
  -> TenantContext
  -> application service
```

## AuthN

O core deve receber identidade de um adapter OIDC/JWT.

No ambiente local:
- issuer de desenvolvimento ou stub assinado;
- nunca espalhar parsing JWT pelos módulos;
- `authn` produz `Principal`.

```go
type Principal struct {
    UserID   uuid.UUID
    Subject  string
}
```

## Persistência e RLS

Todas as tabelas tenant-owned usam `tenant_id`.

RLS deve existir para tabelas críticas já no R0.1.

A conexão/transação deve receber contexto de Tenant de forma controlada antes da query.

Testes devem cobrir:
- A lê A;
- A não lê B;
- A não atualiza B;
- list não mistura A/B;
- membership removida revoga acesso;
- tentativa com UUID conhecido de B continua bloqueada.

## Outbox

Na mesma transação de mudança relevante:

```text
INSERT/UPDATE domínio
INSERT outbox_events
COMMIT
```

Worker:
- busca lote não publicado;
- publica em `evt.*`;
- marca `published_at`;
- retry controlado.
